# Операційний менеджмент

Відкритий навчальний курс «Операційний менеджмент» для першого (бакалаврського) рівня вищої освіти,
НУ «Чернігівська політехніка». Статичний вебсервіс на Astro, опублікований на GitHub Pages, а також
джерело пакетів для завантаження в Moodle.

**Живий сайт:** <https://youngerfornday.github.io/operatsiinyi-menedzhment/>

Стан: рушій перенесено з попереднього курсу кафедри, контент дисципліни пишеться з нуля. Каркас — схеми
контенту, реєстр ідентифікаторів, сховище прогресу, експорт у Moodle, CI і деплой — працює.

## Обсяг курсу

Вибіркова дисципліна, 3 курс, 5 семестр, ОПП «Менеджмент». 6 кредитів ЄКТС, 180 годин: 32 години лекцій,
28 годин практичних занять, 120 годин самостійної роботи. Два змістові модулі, вісім тем.
Оцінювання 60/40: присутність 10, практичні роботи 35, розрахунково-графічна робота 15, екзамен
(тестування) 40 балів.

Силабус наводить 150 годин самостійної роботи, що дає 210 год замість 180 на 6 кредитів; розбіжність
зафіксовано в `docs/research/education-standard.md`, розділ 6, і винесено на звірку з кафедрою.

## Структура

```text
content/                      єдине джерело правди навчального контенту
  course.yaml                 курс: години, реєстр ID модулів, тем, ПРН і термінів, журнал оцінок, шкала, політики
  modules/mN/tNN/             матеріали теми: lecture.mdx, slides.yaml, glossary.yaml, sources.yaml, fig-*.svg
  practicals/pNN.yaml         практичні заняття і дані тренажерів
  banks/training/mN.yaml      тренувальні банки питань (публічні)
  LICENSE.md                  ліцензія контенту (CC BY-NC-SA 4.0)
src/
  content.config.ts           колекції Astro: схема кожного файлу + перевірка цілісності між файлами
  content/schemas/            zod-схеми: курс, тема, глосарій, джерела, банк питань
  content/integrity/          перевірки дублікатів між модулями й відповідності реєстру
  engines/progress/           сховище прогресу студента (localStorage, пам’ять; інтерфейс для SCORM)
  lib/                        url() з урахуванням base, українська множинність
  layouts/, pages/            сторінки сайту
tools/checks/                 перевірка зібраного сайту (npm run check:dist)
e2e/live/                     смоук-тести живого сайту (Playwright)
.github/workflows/ci.yml      перевірки для PR і push, деплой на Pages з main
```

Каталоги `design/`, `docs/research/`, `tools/moodle/` і файли `PRODUCT.md`, `DESIGN.md` містять дизайн-систему,
дослідження і Moodle-інструменти курсу.

## Команди

Потрібен Node.js 22.12 або новіший.

| Команда | Що робить |
|---|---|
| `npm ci` | встановлює залежності точно за `package-lock.json` |
| `npm run dev` | локальний сервер розробки: <http://localhost:4321/operatsiinyi-menedzhment/> |
| `npm run build` | лінт контенту, `astro check` (типи й валідація контенту) і збірка в `dist/` |
| `npm run lint:content` | звіряє факти в `content/` з базами формул і стандартів (див. нижче) |
| `npm test` | модульні тести Vitest |
| `npm run test:coverage` | тести з покриттям; для `src/engines/progress` поріг 80% на файл |
| `npm run check:dist` | перевіряє `dist/` і репозиторій (див. нижче) |
| `npm run test:live` | смоук-тести живого сайту; адресу можна змінити змінною `LIVE_URL` |

Перед першим `npm run test:live` встановіть браузер: `npx playwright install chromium`.

## Контент і валідація

Кожен файл у `content/` валідується zod-схемою; збірка зупиняється на першій помилці.

- **Реєстр ID** у `course.yaml`: модулі `m1`–`m2`, теми `t01`–`t08` (зі slug і назвою), ПРН `prn01`…,
  терміни глосарію. Дублікат ID у реєстрі або між модулями — помилка збірки. Назва, slug і модуль теми
  беруться з реєстру, у frontmatter лекції вказується лише `id`.
- **Джерела** (`sources.yaml`) — кожне з URL і датою перевірки `checkedAt`.
- **Банк питань** дзеркалить типи Moodle XML: `multichoice` (одиночний і множинний вибір, оцінка на кожен
  варіант), `truefalse`, `matching`, `numerical` (з допуском), `calculated` (формула, діапазони наборів даних,
  допуск), `ddwtos` (перетягування в текст), `multianswer` (Cloze). Спільні поля: `id` (починається з ID теми),
  `topic`, `bloom` (`remember` | `understand` | `apply` | `analyze`, у Moodle стає тегом), `stem`, відгук на
  кожен варіант, `generalFeedback`, `refs[]` з джерелом, локатором і датою перевірки. Приклади всіх типів —
  у `src/content/schemas/__fixtures__/questions.ts`.

Внутрішні посилання в шаблонах завжди будуються через `url()` із `src/lib/url.ts`: сайт живе в підкаталозі
`/operatsiinyi-menedzhment/`.

### Лінт фактів: `npm run lint:content`

Схема перевіряє форму, лінт — зміст: те, що доти ловили лише люди читанням. Для розрахункової дисципліни
джерела істини — `docs/research/formula-baseline.md` (формули з позначеннями, одиницями, допущеннями й
джерелом) і `docs/research/standards-baseline.md` (ISO, ДСТУ). Правила лежать у
`tools/checks/content-lint/rules/`:

1. **Коди формул і стандартів** — кожен код у `refs`, `<StandardRef>`, `<Formula>` і `<WorkedExample>` є
   в базі, а джерело збігається з тим, що записано для коду.
2. **Узгодженість посилань** — коди в тілі лекції та у слайдах збігаються з `refs` у frontmatter теми.
3. **Заборонена зона** — твердження про пункт розділу «Не підтверджено» (попередження).
4. **Дати перевірки** — `checkedAt` не в майбутньому і збігається з датою, яку фіксує база для коду.
5. **Застереження кейсів** — причинні сполучники там, де `caveat` вимагає паралельних фактів.
6. **Джерела** — невикористаний запис `sources` (попередження), посилання `source:`/`#src-…` в нікуди (помилка).
7. **Терміни** — `<Term>` вводить лише термін своєї теми, з визначенням у `glossary.yaml` і в `keyTerms`.
8. **Числа без джерела** — відсоток, сума чи співвідношення без `source:`, коду формули чи згадки джерела
   в межах абзацу (евристика, попередження).
9. **Баланс відповідей** — правильна відповідь не скупчується в одній позиції й не видає себе довжиною
   (і в `<SelfCheck>`, і в банках питань).

Прапорці: `--fix-hints` (як виправити кожну знахідку), `--strict` (попередження = помилки),
`--warn-only` (завжди код 0). Лінт блокує збірку: `--warn-only` у `scripts.build` прибрано.

## Контрольні банки і canary

Контрольні банки питань зберігаються **лише в приватному репозиторії**. Схема банку спільна, але контрольний
файл обов’язково містить поле `canary` з префіксом `CONTROL_CANARY_PREFIX` (див.
`src/content/schemas/questions.ts`). Сам рядок-маркер у публічному репозиторії не записується навіть у коді:
`npm run check:dist` падає, якщо знаходить його в будь-якому файлі репозиторію (крім `node_modules`) або
в `dist/`. Та сама перевірка ловить посилання `href="/…"` і `src="/…"` без base.

## Прогрес студента

Прогрес зберігається в `localStorage` під ключами з префіксом `om:v1:` (домен спільний з іншими сайтами
автора, тому префікс окремий для цього курсу). Дані мають версію схеми з міграціями; пошкоджені дані не видаляються мовчки, а копіюються в резервний
ключ. Без доступу до сховища сайт працює, а прогрес живе до закриття вкладки. Код прогресу для перенесення між
пристроями перевіряється схемою та обмежений за розміром.
